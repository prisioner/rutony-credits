# Архитектура и данные

## Компоненты и причины решений

| Компонент | Ответственность |
|---|---|
| `integration/rutony_credits.cs` | Подписка на публичные OnFollower, OnAnySubscriber, OnRaid, OnDonate, OnChatMessage; отключение в Closing |
| `RuntimeHost` | Узкая reflection-граница скрипта и DLL; нормализация vkplay в VK Video Live |
| `RutonyRaidSource` | Пассивный локальный `/AlertsList` для Twitch-рейдов, reconnect и единственный Twitch ingress |
| `CreditStore` | Очередь событий и команд, JSONL-журнал, периоды, восстановление и снимки |
| `CreditsServer` | Kestrel на IPv4 loopback, страницы и JSON-команды с проверками Host/Origin |
| `ObsController` / `ObsProtocol` | Локальный WebSocket v5, Program-переходы, состояния трансляции и повторное подключение |
| `ObsSettingsStore` | Несекретный obs.json и отдельный DPAPI-пароль текущего Windows-пользователя |
| `web/` | Панель управления и однократная/циклическая прокрутка снимка в OBS |

Производственный runtime живёт внутри RutonyChat. Отдельный PreviewHost
используется только как стенд. Фолловеры, подписки, донаты и VK-рейды приходят
публичными делегатами. Исследованный SendAlertRaid не вызывает
ScriptsControl.NewAlert, второго пути NewAlert/NewAlertEx нет. Twitch обходит
общий OnRaid и отправляет рейд напрямую в оверлеи, поэтому для него используется
пассивный Event List. OnDonate обрабатывается независимо от источника события.

Оповещательные делегаты не дают признак test, исходный ID или время источника. Поэтому
используются время получения и последовательность; имена оповещений не
дедуплицируются (модераторы имеют отдельный контракт ниже). Тестовое событие, пришедшее штатным делегатом RutonyChat,
невозможно отличить от настоящего. Наш preview использует отдельный
искусственный снимок и не отправляет глобальных оповещений.

## Жизненный цикл в RutonyChat

RutonyChat может вызывать InitParams и Closing в потоке интерфейса.
Синхронная reflection-граница RuntimeHost выполняет запуск и полную
очистку через Task.Run без UI SynchronizationContext. Вызывающий поток
дожидается результата: Closing завершается после остановки HTTP,
завершения текущей работы и закрытия файлов. Фоновая незавершённая
очистка после возврата из Closing не оставляется.

Это предотвращает взаимное ожидание UI и async continuation при изменении
или удалении пресета. Повторный запуск использует прежние данные и
освободившийся порт. Долгое стороннее событие или сбой диска всё ещё
может задержать завершение; цикл жизни в настоящем RutonyChat проверяется
отдельным ручным прогоном.

## Очередь и показ

Обработчик только ставит запись в очередь; диск обслуживает один worker.
Запуск и сброс проходят через ту же очередь: снимок содержит ранее
принятые записи, события после сброса относятся к новому периоду.
Во время показа сбор продолжается. Оформление и события фиксируются на
старте. Пустые и выключенные разделы скрываются. Loop фиксируется в
snapshot и не изменяется от последующего сохранения настроек; завершение
одного цикла не завершает loop-run. Stop останавливает оба режима.

При перезапуске восстанавливаются журнал и настройки, показ остаётся
остановленным. Повреждение журнала блокирует реальные титры до явного
нового периода. Ошибка записи или переполнение помечают период неполным;
маркер сохраняется, если диск доступен. Полностью отказавший диск не
может надёжно сохранить сообщение о собственном отказе.

## Каталог данных и параметры скрипта

По умолчанию данные находятся в пользовательском
`LocalAppData/RutonyCredits`, отдельно от пакета.
`DataDirectory` в параметрах автономного скрипта позволяет выбрать
другой доступный для записи каталог. Пустое значение оставляет стандартный
каталог. При переносе остановите скрипт и сохраните весь прежний каталог,
включая настройки, manifest и `sessions/`; пустой новый каталог создаст
новый период. Не направляйте два работающих экземпляра в один каталог:
`writer.lock` удерживается с исключительным доступом.

`PackageDirectory` по умолчанию равен `scripts/RutonyCredits`
в установленном RutonyChat; внутри находятся DLL и `web/`.
Параметр `Port` по умолчанию равен 18765, допустимы 1024–65535.
Файл `integration/rutony_credits.json` задаёт форму этих параметров
RutonyChat; он не является файлом оформления `settings.json`.

### settings.json

Настройки сохраняются кнопкой «Сохранить оформление» в панели и
применяются к следующему показу. До первого сохранения файла может не
быть: используются значения по умолчанию. Формат JSON — camelCase:

```json
{
  "fontFamily": "Arial",
  "fontSize": 48,
  "speed": 80,
  "textColor": "#ffffff",
  "loop": false,
  "aggregateDonations": false,
  "moderatorExclusions": [],
  "enabledSections": {
    "vk-raids": true,
    "twitch-raids": true,
    "donations": true,
    "followers": true,
    "subscribers": true, "moderators": true
  },
  "headings": {
    "vk-raids": "Рейды VK Video Live",
    "twitch-raids": "Рейды Twitch",
    "donations": "Спасибо за поддержку",
    "followers": "Новые фолловеры",
    "subscribers": "Новые подписчики",
    "moderators": "Модераторы"
  }
}
```

`fontFamily` — имя установленного шрифта, 1–100 символов без управляющих
знаков; `fontSize` — 16–160 логических px; `speed` — 10–400 логических
px/с; `textColor` — `#RRGGBB`. В `headings` нужны шесть указанных
ключей, каждый заголовок непустой, до 120 символов без управляющих знаков.
EnabledSections содержит те же шесть ключей с boolean-значениями; Loop —
boolean, по умолчанию false. При отсутствии новых полей в прежнем JSON
сохраняются один проход и все включённые разделы. Отсутствующая новая
moderators достраивается при чтении прежнего набора пяти секций.
AggregateDonations — boolean, по умолчанию false. Словари глубоко копируются
между входными настройками, текущим состоянием и snapshot.
Безопаснее менять оформление через панель. Ручное редактирование делают
после остановки скрипта с копией файла; некорректная конфигурация вызывает
ошибку восстановления.

### current.json и sessions/

`current.json` содержит JSON-строку с ID активного периода: GUID без
дефисов, 32 шестнадцатеричных символа. Его журнал —
`sessions/<id>.jsonl`: одна запись события на строку. Поля:
`sessionId`, `eventId`, `sequence`, `source`, `platform`, `kind`,
`displayName`, `receivedAtUtc`, `occurredAtUtc`, `sourceEventId`.
Скрипт пишет источник `rutony`, текущее время получения; исходные
время и ID остаются null, поскольку делегат их не передаёт.
Для доната добавлены optional amount (decimal) и currency (код исходной
валюты, 1–12 латинских букв/цифр). Прежние JSONL без этих полей совместимы.
Тонкий скрипт использует штатные SumClass.sum и currency.CharCode,
преобразует float через invariant round-trip строку в decimal и вызывает
RecordDonation. Код валюты trim/ToUpperInvariant: USD и usd одинаковы.
Знаки вроде $ не преобразуются в USD по догадке. Некорректные/неизвестные денежные сведения не превращаются
в выдуманную сумму: native-вход сохраняет имя без этих полей.
Record из трёх параметров остаётся для остальных событий и старого скрипта.
Names в snapshot — безопасные текстовые строки с именем, суммой и валютой.
Текст доната и сырые payload не сохраняются.

Команда «Сбросить счётчики» создаёт новый журнал и переключает `current.json`,
сохраняя прежние файлы. `sessions/<id>.incomplete` отмечает неполный
период. Не редактируйте журнал или manifest для устранения ошибки:
сохраните копию данных, устраните проблему диска и явно начните новый
период. Реальные журналы и личные параметры не входят в Git и пакет.

## Системные шрифты

GET /api/fonts возвращает string[] имён семейств текущего Windows-пользователя
через EnumFontFamiliesExW, без дубликатов стилей и vertical @-алиасов.
Пути файлов и файлы шрифтов не передаются. Список запрашивается при открытии
панели; свободный ввод остаётся доступен при пустом списке/ошибке.
На другой ОС каталог пуст, остальные настройки продолжают работать.
[Windows API](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-enumfontfamiliesexw)

## HTTP и OBS

Сервер слушает только `127.0.0.1`; занятый порт вызывает ошибку.
Он не регистрирует ConsoleLifetime и не завершает RutonyChat.
Управляющие POST требуют JSON и отдельный токен страницы управления.
OBS URL этого токена не содержит; завершение показа использует отдельный
токен конкретного запуска. Это локальный интерфейс без отдельного логина.

Экран использует логическую область 1920 × 1080 и масштабирует её
в Browser Source. Сервер задаёт время старта: перезагрузка страницы
продолжает текущий показ. Строки добавляются через textContent, фон OBS
прозрачный. Фон preview задаётся отдельно для читаемости.

Реальная доставка событий и OBS требуют [ручной проверки](../manual-test.md).

## Агрегирование и модераторы

AggregateDonations влияет только на snapshot. Группа — ник без учёта регистра
и код валюты в верхнем регистре, независимо от сервиса. Ключи ника и валюты
нормализуются через ToUpperInvariant. Написание в показе берётся у первого
доната группы в хронологическом порядке; исходный displayName не меняется.
Строка на месте первого доната группы; сумма decimal без конвертации.
Неизвестные суммы остаются отдельными. При переполнении decimal все
исходные строки этой группы сохраняются по порядку вместо неверного итога.

OnChatMessage передаёт site/name/text и Dictionary<string,object>.
Подтверждённый mapper Rutony кладёт moderator(bool) и user_id/userId(string).
Принимается только явный bool true для Twitch/VK; текст не сохраняется.
RecordModerator строит стабильный SHA-256 identity из user ID, fallback —
нормализованный ник; sourceEventId исключает повторные сообщения того же
модератора в периоде. В показе/счётчике moderators ники уникальны без учёта
регистра. Никаких новых запросов авторизации Twitch/VK нет.

Сохранённые ModeratorExclusions проверяются worker до Append/dedup, в FIFO-порядке
с SetSettingsAsync. Пропущенная запись не занимает sequence или sourceEventId.
Старые исключённые moderator-записи остаются в JSONL, но не входят в EventCount,
поэтому не создают предупреждения RuntimeHost о непустом периоде. Снятие
исключения возвращает ранее сохранённые записи; остальные kind не фильтруются.

## Настройки OBS и уведомления

GET /api/obs возвращает ObsStatus (options,connected,phase,error,hasPassword,
scenes,available,pendingResetUntilUtc). Стенд имеет available=false. POST /api/obs требует тот
же management token и JSON с options/password/clearPassword. Null/пустой
пароль сохраняет прежний; clearPassword удаляет сохранённый секрет.
Пароль не возвращается в status, обычный settings.json или текст ошибки.

В каталоге данных obs.json хранит enabled,port,sceneName,autoStart,
resetOnStop,resetDelayMinutes (default5, целые1..120 минут). obs-secret.bin — Windows DPAPI текущего пользователя.
Подключение выключено по умолчанию, host фиксирован 127.0.0.1, порт4455.
Пустое имя сцены допускает первое подключение для получения списка;
автозапуск включается после выбора сцены. Настройки переживают перезапуск.

Первичное подключение и reconnect дают baseline без Run/Reset. Только
последующие Program-переходы управляют показом. STOPPING→STOPPED после
известного активного потока в одном соединении планирует одноразовый Reset
через ResetDelayMinutes. RuntimeHost захватывает sessionId на STOPPED.
Монотонный TimeProvider задаёт ожидание, UTC deadline служит только панели.
После срока fresh GetStreamStatus обязан подтвердить inactive и !reconnecting.
ObsProtocol использует один receiver: op5 события, op7 ответы pending-запросов;
обработчик STOPPED запускает timer task, не ожидая его сетевого ответа.

STARTING/STARTED/reconnect/разрыв, изменение/отключение подключения OBS
и ручной reset отменяют ожидание. Отмена и sessionId повторно проверяются внутри команды
CreditStore.ResetIfCurrentAsync в той же очереди, что события/ручной reset.
Уже начатые команды дожидаются lifecycle, поэтому после подтверждённого
отключения не остаётся позднего reset. Epoch соединения задаётся linked
cancellation scope; старый запрос/таймер не переходит в новый baseline.
При штатном RuntimeHost.Dispose внутренний ObsController.CloseAsync
захватывает sessionId ещё ожидающего сброса до собственного cancel. Затем
останавливает receiver/timer и дожидается всех начатых команд. RuntimeHost
передаёт захваченный период в терминальный CloseAsync store. Одна зарезервированная
команда в конце FIFO проверяет период и выполняет сброс после drain даже
при полном бюджете обычных команд.
Уже заменённый период не очищается; завершившийся таймер не даёт повторного
сброса. HTTP закрывается раньше OBS, store последним; истёкший таймер
может завершить корректный reset, пока store ещё открыт. UI callback
при этом подавляется. Обычный DisposeAsync контроллера при failed startup
только отменяет ожидание. Закрытие без pending ничего не очищает.

Отключение/удаление/перезапуск скрипта и обычный выход Rutony используют
один Closing и завершают активное ожидание одинаково. Признак штатного
выхода всего приложения, Steam handles и exit marker не требуются.
PendingResetUntilUtc — временный status, не сохраняемое задание; рестарт
ничего не возобновляет. Краш/Kill не вызывает штатный Closing. Error/timeout/active/reconnecting сразу снимают pending до предупреждения,
чтобы параллельное закрытие не превратило сохранение в сброс. Неожиданный STOPPED также сохраняет период. Причина
остановки протоколом не доказана.

Native SetNotificationHandler вызывает SayToWindow напрямую, как стартовый
banner: публичный SDK передаёт сообщение в WebSocket broadcast без обращения
к UI. Захваченный WinForms SynchronizationContext может не обслуживаться,
поэтому Post не используется. Closing не зависит от выполнения UI callback.
Callback закрытого или заменённого экземпляра ничего не отправляет. При запуске проверяется
количество восстановленных событий до подписки на новые; на STARTED —
текущий период. Сообщение содержит полный URL панели, без секретов.
Порядок закрытия: HTTP, OBS worker, очередь/store. Все операции выполняются
без унаследованного UI context; активный store barrier завершается до
подтверждения отключения OBS.

## Исключения модераторов и ведущий

ModeratorExclusions — optional string[], default[]. Validate принимает до50
ников по200 символов после trim/одного leading@; control chars/null/пустой
элемент отклоняются. Backend удаляет повторы OrdinalIgnoreCase, глубоко
копирует массив между входом/settings/state/run. Панель дополнительно
проверяет размер всего UTF-8 POST, чтобы сохранить введённое при превышении
лимита HTTP. Настройки хранятся в прежнем settings.json.

Исключения влияют на Names/moderators и её текущий счётчик, не на первичный
JSONL или другие секции. Замороженный run остаётся неизменным.

Native использует GetParent/GetChatServer → публичный GetChannelPath для
Twitch login. Для VK текущий internal-коннектор имеет public ServiceAPI:
поле читается reflection, без private credentials. Только при service.State=OK
и OAuthBase.State=ready выполняется один GetChannelInfoAsync с timeout5с
для текущего API/канала до его смены. Метод использует свою существующую авторизацию;
расширение не получает токены и не запускает login. При null/error/timeout
повторов нет, ручные исключения доступны. Метод Rutony при ошибке может
сам обновить состояние API/вывести системное сообщение. Это ограниченный
версионный adapter, не документированное универсальное API всех версий.

SetChannelContext передаёт текущий platform/channel, а SetChannelOwnerForContext —
наблюдённые имя/ID вместе с тем же контекстом. Старый SetChannelOwner сохранён
для совместимости: наблюдение без контекста действует только в текущем
процессе и не активируется из cache после рестарта. ID хэшируется так же, как
sourceEventId модератора. Поэтому смена отображаемого ника VK не мешает
исключению владельца по ID. Twitch сравнивается по login без учёта регистра.
Отложенный результат проверяет экземпляр runtime, cancellation, актуальные
API/канал и поколение lookup; ответ прежнего подключения не заменяет
текущего владельца. Проверка актуального API/канала повторяется внутри
ownerGate непосредственно перед публикацией. Смена API/канала разрешает новый lookup.
Native проверяет контекст при событиях и раз в секунду, в том числе без чата;
неизменный контекст не создаёт команд и дополнительных owner-запросов. Closing
отключает опрос, очищает runtime под тем же lock и
не ждёт UI или сетевого lookup. Guard разрешения не вызывает новый вход.

Производный cache sessions/<period>.owners.json содержит platform→name/eventId/context
(хэш ID, без токенов). Он сохраняется вместе с текущим периодом и архивом;
при новом периоде cache переносится. При старте cache не активен до получения
текущего контекста от native; совпадающий канал может использовать его даже
без ready OAuth. Неизвестный или другой канал не использует прежнего владельца.
Legacy cache без context читается безопасно, но требует нового наблюдения.
Повреждение или
ошибка записи optional cache не блокируют первичный журнал/HTTP, identity
можно получить повторно через Rutony. Старые периоды без cache совместимы.

## Явные ссылки в Rutony

Legacy default не делает autolink plain URL. SayToWindow передаёт текст
в msgClass.text; поставляемый jquery.tmpl оставляет HTML. Поэтому native
экранирует текст и подставляет только собственные anchors с фиксированными
подписями, loopback href/проверенным портом, target=_blank и rel=noopener
noreferrer. Подпись не содержит URL, чтобы default-v2 не создал вложенный
anchor. Это не требует изменения темы и не вызывает connection-state API.
Ссылки Credits ведут только на Credits; вывод уведомлений также использует
этот formatter. Реальный клик из выбранной темы требует ручной проверки.


### Точные локальные начертания

`GET /api/font-faces?family=...` возвращает до двух metadata-объектов
`{localName, weight}` для точного семейства из GDI-каталога. `/api/fonts`
сохраняет прежний `string[]`; неизвестное семейство даёт `[]`, недопустимый
или повторённый query —400. Файлы шрифтов не читаются и не раздаются.
`EnumFontFamiliesExW` с непустым family получает `elfFullName` каждого face,
включая CFF/OTF; дубликаты charset и italic исключаются.

У legacy family собственный Regular может иметь native weight250,600,900.
Resolver выбирает upright с ближайшим к400 весом (при равенстве меньший),
а отдельный более тяжёлый face — ближайший к700. Их CSS descriptors равны
400/700. Единственный face регистрируется только при400: заголовок сохраняет
браузерный синтез жирного. Локализованные названия не разбираются по словам.

Overlay связывает точные `local()` names с внутренним FontFace alias,
сохраняя выбранное имя в настройках/UI. CSS strings экранируются; источники
сетевых шрифтов не создаются. Endpoint/FontFace имеют общий timeout1200мс;
неизвестное имя, старый backend, неподдерживаемый API и отказ загрузки
оставляют прежнее CSS family. После Stop/newrun старое ожидание не меняет
экран, добавленные faces освобождаются. Измерение идёт после загрузки,
время ожидания входит в elapsed прокрутки. State polling продолжается
во время загрузки metadata и face.

## Ограничения чтения и восстановление

Журнал и оформление имеют независимые типы fault. Ошибка settings.json
блокирует реальный показ, но сбор событий продолжается. Успешное «Сохранить
оформление» снимает только settings fault; Reset снимает только fault
старого периода. Ошибка первичного журнала не исчезает от Save. Перед явной
заменой повреждённых settings/current сохраняется файл .recovery-<guid>;
старые JSONL и маркеры неполноты остаются в sessions.

Чтение small files проверяет размер и ограничивает фактически прочитанные
байты даже при росте файла. Лимиты: settings —256KiB, current —4KiB,
owner cache/obs.json/защищённый пароль —64KiB; шаблон control.html —1MiB.
JSONL читается потоково, до16384 UTF-16 code units на строку, включая JSON
escapes. Лимиты с запасом покрывают все генерируемые текущим контрактом поля:
50×200 исключений плюс заголовки, имена/ID/валюты событий, контекст канала
до2048 и защищённый пароль до4096 знаков. Количество нормальных событий
и суммарный размер журнала не ограничены; журнал не усекается.

Повреждённый/слишком большой OBS secret требует явного нового пароля либо
флага очистки. Сохранение остальных OBS-параметров не скрывает такой отказ.
Исходный ciphertext копируется потоково в .recovery-<guid>; не требуется
декодировать повреждение или размещать большой файл в памяти. Если запись
obs.json не удалась, secret восстанавливается через временный файл из backup;
backup остаётся и при сбое rollback. При исправлении только obs.json рабочий
пароль перечитывается и остаётся в памяти без перезапуска.

## Admission и перегрузка

Один FIFO worker обслуживает до10000 незавершённых записей и общий бюджет
до256 команд, включая State/Run/settings/reset и owner updates. Физический
Channel ограничен10772 элементами: дополнительное место предназначено только
для маркеров потерь, контекстной инвалидизации и единственного terminal Close.
WriteAsync/ожидающих writers нет. Отклонённая команда сразу возвращает
StoreOverloadedException (HTTP503), owner method —false. OBS configuration
и ручная отмена reset также отклоняют занятую lifecycle-операцию через503;
Closing дожидается уже начатой операции.

Потеря Record создаёт один ordered incomplete marker на ingress epoch;
принятый reset меняет epoch. Отклонённый reset не меняет epoch. При отказе
контекстной команды ставится safety marker, отключающий текущего владельца:
неизвестный новый канал не наследует чужой cache. Такие markers объединяются
только пока между ними не принята контекстная команда той же платформы.
Их число ограничено количеством ожидающих context commands плюс две
платформы; они не обгоняют уже принятые snapshots. Native забывает подтверждение
отклонённого контекста и повторяет его публикацию при следующем наблюдении.

## Источник рейдов Twitch

Native читает только public ChatLocalServer._HttpServer и его IsListening/Port/
IsSecure, сразу и существующим секундным timer. ConfigureRutonyRaids(port,secure)
передаёт состояние DLL; endpoint строится внутри DLL только на IPv4 loopback,
ws/wss `/AlertsList`, без proxy и без отключения проверки TLS.

Подтверждённый пакет: `{type:"Raid",data:{name,qty,site,site_img,tag}}`, site Twitch.
Потребитель не отправляет init или других команд: у изученного сервера OnOpen
не воспроизводит историю. Принимаются только отдельные Twitch Raid objects;
другие типы/площадки, arrays, binary, malformed и oversized сообщения пропускаются.
Буфер ограничен64KiB, connect timeout5s, partial-frame10s, reconnect2s.

После первого выбора потока generic Record(twitch,raid,...) не принимается
до завершения RuntimeHost, включая временное отсутствие сервера. Смена порта
сначала полностью отменяет прежний worker. Это исключает double-count из двух
путей при возможном исправлении OnRaid самим Rutony. VK не меняется. До первого
обнаружения сервера остаётся legacy fallback; панель показывает ожидание источника.

Нет event ID/timestamp/test flag: одинаковые реальные рейды не склеиваются;
встроенный тест Rutony может учитываться как реальный. Пропуски за время разрыва
не восстанавливаются. При Closing источник отменяется до закрытия журнала,
очистка дожидается worker без UI-контекста. PreviewHost поток не подключает.

`/api/state.twitchRaids` содержит available/connected/phase/error; это transient
диагностика соединения, без payload/секретов. Журнал, настройки и snapshots
сохраняют формат. Только принятый ник записывается как обычный Twitch raid.
