# Качество и границы доказательств

## Автоматические проверки

`./scripts/build.ps1 -Check` запускает проверки на изолированных временных
данных и собирает Release без внешних NuGet-пакетов. Проверяются:

- повторные имена и дедупликация только надёжного source ID;
- порядок событий и неизменяемый снимок показа;
- барьер сброса, сохранность прежнего журнала и отклонение старых команд;
- восстановление периода и оформления без автоматического запуска;
- отдельный preview и завершение только текущего запуска;
- повреждение журнала, отсутствие manifest, ошибка диска и переполнение;
- HTTP-токен, Origin/Host, JSON, коллизия порта и жизнь сборщика
  после остановки HTTP;
- координаты и конец прокрутки в логической области OBS;
- запуск и полная остановка в непомпящем UI SynchronizationContext:
  незавершённая очередь, сохранность события, повторный захват того же
  порта/каталога. Watchdog освобождает тест только после фиксации сбоя.

Новые проверки: старые JSONL/settings без новых полей, отдельные суммы и
валюты повторных донатов, выключенные/все выключенные секции, immutable
loop snapshot, реальный GDI font catalog через HTTP. Отдельный native test
проводит событие через actual rutony_credits.cs в хранилище/HTTP snapshot,
включая ru-RU, большие float-суммы и снятие подписок при Closing.
JS-тесты проверяют combobox с клавиатурой/кириллицей, режимы сохранения,
границы циклов, повторное открытие overlay, конечное завершение и Stop.

Изменения поставки также требуют проверки состава пакета, локальных
ссылок в документации и отсутствия внешних локальных зависимостей.
В Git не входят `bin/`, `obj/`, `dist/`, `.runtime/`, `.local/`,
данные пользователя, секреты и бинарники RutonyChat.

## Ручные проверки

На синтетических данных в браузере проверяются тестовый показ,
настройки, остановка, завершение прохода и перезагрузка страницы.
Launcher проверяется со стандартным и изменённым портом, а также
недопустимым вводом. Компиляция native-скрипта против установленной
RutonyChat.dll — отдельная проверка совместимости сигнатур.

Реальная загрузка скрипта в интерфейсе RutonyChat, все категории
событий сервисов и установленный OBS Browser Source требуют
[ручного прогона](../manual-test.md). До такого прогона это **NOT RUN**.
Наличие обработчика и успешные синтетические проверки не подтверждают
production-доставку. Кликабельность напечатанного через SayToWindow
адреса в выбранной пользователем теме RutonyChat также не подтверждена;
статически установлен механизм URL→anchor штатной default-v2.

Не создавайте платежи или глобальные оповещения только ради теста.
При описании результата указывайте команду, область и ограничения:
отсутствие проверки не означает успех.

[Разработка](development.md) · [Архитектура](architecture.md)

Дополнительные регрессии: агрегирование/overflow/первое время без изменения
журнала, legacy five→six sections, уникальные модераторы; native проверяет
явный boolean роли, отсутствие текста чата и неблокирующие уведомления.
Fake WebSocket v5 проверяет challenge auth, baseline/race, Program/Preview,
повторы, reconnect, штатный/неожиданный stop, DPAPI/rollback/no-secret и
cancellation. End-to-end RuntimeHost+HTTP с fake OBS проверяет настоящий
snapshot, reset/архив и предупреждения после пропущенного stop/рестарта.
JS: обе dirty-формы, revert, failed save, изменения во время запроса,
password preserve/clear, выбор сцены и сохранение пользовательского ввода.

Повреждённый или чрезмерно большой obs.json изолируется как ошибка OBS:
сбор событий и HTTP титров продолжают работать. Recovery regression
проверяет JSON null, размер более64KiB и сохранение новой конфигурации.

Проверки исключений: trim/@/регистр, сохранение/restart, legacy default[],
влияние только на секцию модераторов/счётчик, неизменность журнала и run,
deep copy и недопустимые списки. Owner identity проверяется по имени/ID,
её derived cache переживает restart и изолирует повреждение. Native fake
проверяет настоящий HTML formatter, escaping, Twitch/VK owner adapter,
ready-auth guard, один запрос на текущий контекст API/канала и late result после Closing.
Компиляция native-скрипта против установленного SDK — отдельная
проверка сигнатур; фактическая авторизация/owner response остаются NOT RUN.

Native concurrency regressions отдельно меняют API instance и канал на том
же API во время незавершённого owner GET. Поздний ответ A не перезаписывает
владельца B; повторные сообщения не делают лишних запросов одного контекста.


Отложенный OBS reset проверяется управляемым MonoTimeProvider без NuGet:
нет reset до deadline, stop/start в4:59, полный срок повторного stop,
одноразовый expiry и сохранный архив. Перевод UTC вперёд/назад не ускоряет
монотонное ожидание. Fresh GetStreamStatus: inactive, active, reconnecting,
ошибка, timeout и неполный ответ; неопределённость сохраняет период.
Cancel матрица: STARTING/STARTED/RECONNECTING/RECONNECTED, connection loss,
configure/disable/dispose, manual reset и рестарт без replay. Блокировка
storequeue воспроизводит reset, уже поставленный до STARTING/configure/
dispose/manual cancellation: token/session guard выполняется в очереди,
lifecycle дожидается барьера. Runtime HTTP проверяет ручной новый период,
снятие pending status и отсутствие позднего удаления новых событий.
JS проверяет legacy default5, сохранение/dirty/границы1..120 и pending UI.
Реальные технический stop/start, завершение с ожиданием и разрыв связи
остаются NOT RUN до самостоятельной проверки стримером.

Проверки локальных faces: синтетический выбор weights/italic/charset,
один Black/Thin/SemiBold face и локализованный Bold; HTTP unknown/bounds
и реальные Windows Arial Regular/Bold. JS проверяет точные local sources,
CSS escaping, distinct bold/синтез, ошибки/timeout/старый backend/API,
позднее завершение и освобождение faces, Stop/newrun во время загрузки,
учёт ожидания в elapsed. Внешние шрифты не являются зависимостью CI.
Фактический физический face проверяется отдельно через browser platform
fonts; computed CSS само по себе не доказывает выбор файла. Установленный
OBS/CEF остаётся отдельной ручной приёмкой.


## Закрытие при ожидающем сбросе

ClosingResetChecks проходит реальный RuntimeHost/HTTP/OBS/store: подтверждённый
стоп, закрытие на 4:59 и восстановление дают пустой новый период с прежним
JSONL. Отсутствие stop, неожиданный stop, STARTING, потеря связи, ручной новый
период, изменение настроек OBS и уже завершившийся таймер сохраняют текущий
период при закрытии. Закрытие выполняется с замороженным UI context.
Отдельная блокировка очереди проверяет drain уже начатого reset, защиту
заменённого периода, повторный close и отсутствие двойного сброса.
Синтетический сервер не доказывает штатную доставку lifecycle конкретной
версии Rutony/OBS: ручной stop→закрытие→запуск остаётся отдельной проверкой.

Регрессия fresh active/reconnecting/error блокирует уведомление о сохранении
данных и одновременно вызывает CloseAsync. После небезопасного ответа право
сброса уже отозвано; закрытие ждёт drain, а период остаётся непустым.


## Предупреждения без UI pump

NativeChecks запускает настоящий integration/rutony_credits.cs с непустым
восстановленным периодом и SynchronizationContext, чья Post-очередь никогда
не исполняется. Предупреждение должно дойти до SayToWindow без Drain.
Захваченный callback старого runtime после Closing и после reinit ничего
не отправляет. Проверки денег, событий и ссылок остаются в том же прогоне.
Реальная доставка в выбранной теме проверяется отдельно; возврат SDK
SayToWindow сам по себе не является подтверждением рендера браузером.

## Storage и bounded admission

StorageRecoveryChecks воспроизводит независимые settings/journal faults:
Save→restart, Reset при плохом оформлении, совместное повреждение,
сохранение исходных settings/current bytes. Corrupt и oversized OBS secret
проверяются с заменой и очисткой, рестартом, ошибкой obs.json и rollback;
отдельно проверяется retained password после восстановления только options.
Проверяются точные границы small files/JSONL, maximum legal escaped fields
и журнал12000 событий без общего ограничения числа/размера.

AdmissionChecks блокирует реальный worker, насыщает общий бюджет owner/read
commands, проверяет мгновенный отказ и HTTP503, Close drain принятой записи,
восстановление admission и отсутствие ожидающих OBS lifecycle writers.
ClosingResetChecks дополнительно закрывает runtime с pending reset при
насыщенной очереди. Прежние overflow/reset/cancellation races сохраняются.

OwnerContextChecks проверяет legacy cache, неизвестный/совпадающий/другой
канал, restart/reset и late foreign result. При2000 rejected context updates
проверяется порядок: старые принятые чтения сохраняют прежнюю фильтрацию,
новые не применяют чужого владельца. Native fake проходит насыщение/повтор
публикации, смену канала без чата, no-ready OAuth без нового login, отсутствие
повторного HTTP на неизменном контексте и отсутствие опроса после Closing.
Реальные аккаунты, реальные журналы и доставка событий сервисов этими
проверками не подтверждаются.

## Изолированный Twitch raid ingress

Core fake WebSocket проверяет реальный RuntimeHost: формат Event List,
фрагментацию UTF8, неполные/повреждённые/oversized/binary сообщения, другие
площадки и типы, отсутствие init, реальные повторы, generic+stream single
source, reconnect/смену порта, secure mode и Closing при зависшем handshake/
partial read. Native fake публичного сервера проверяет автопоиск порта,
замену сервера, VK и UI Closing/reinit. Browser check проверяет статус.

Compile-only против изученной RutonyChat.dll подтверждает public reflection
boundary без исполнения настоящего SDK. Живой рейд из Twitch и совместимость
с другой сборкой Rutony требуют ручной проверки. Тесты не доказывают восстановление
пропущенных рейдов или распознавание test/id, которых нет в Event List payload.

## Проверка содержимого репозитория

```powershell
pwsh -NoProfile -File scripts/check-publication.ps1
pwsh -NoProfile -File tests/publication.tests.ps1
```

Scanner читает текущие Git-tracked файлы и историю, достижимую из всех
локальных refs, включая удалённые файлы и commit/tag metadata. Он не читает
ignored/untracked файлы, Git config, переменные среды или реальные credentials;
reparse points не разыменовываются. Проверяются известные сигнатуры токенов
и private keys, собственные runtime-имена и переносимость Markdown-ссылок
в текущем дереве. Ссылки должны вести в tracked содержимое клона либо на
HTTP(S)/mailto; машинные пути и выход за пределы клона запрещены.

Это ограниченный scanner: неизвестные форматы секретов и доступность внешних
ссылок он не проверяет. История должна быть полной; shallow clone даёт ошибку.
Remote-only refs, reflogs и недостижимые объекты не входят в проверку.
Вывод содержит категории и количества без значений совпадений;
предупреждение о non-noreply email не меняет Git identities.
Scanner ничего не публикует и не переписывает историю.
