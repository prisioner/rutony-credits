# Совместимость Rutony Credits с .NET runtime

Расширение собирается для net9.0 и загружается внутрь
RutonyChat; установленный runtime самого Rutony определяет исполнение.
Переключение TargetFramework расширения на net10.0 не обновляет host9.

## Текущий контракт

Изученный Rutony SDK/runtimeconfig — .NET9; основной пакет сохраняет net9.0.
Для изолированных проверок ядра и native-контракта используется отдельная
копия runtimeconfig и CLI roll-forward Disable. Компиляция тонкого скрипта
против RutonyChat.dll проверяет сигнатуры SDK; синтетические проверки
не подтверждают загрузку в реальный host, GUI или авторизацию сервисов.

| Host | Библиотека расширения | Статус |
|---|---|---|
| Изученный Rutony9 | net9.0 | Основной поддерживаемый SDK/формат пакета |
| Изолированный test host9 | net9.0 | Синтетические core/native проверки на явно выбранном runtime |
| Изолированный test host10 | net9.0 | Синтетические проверки; поддержка реального host требует отдельного прогона |
| Rutony9 | net10.0 | Такой пакет не поставляется |
| Будущий официальный Rutony10 | net9.0 | Нужны actual SDK compile и ручная загрузка на выбранной версии |

## Как повторить безопасно

Нужны уже установленные .NET SDK/runtime и Node для основной сборки.
Команды выполняются из этого клона, без рабочего Rutony или аккаунта:

```powershell
./scripts/build.ps1 -Check
./scripts/check-runtime-compatibility.ps1 -RuntimeVersion 9.0.2
./scripts/check-runtime-compatibility.ps1 -RuntimeVersion 10.0.9
```

Вместо patch-версий примера укажите имеющуюся полную версию из
`dotnet --list-runtimes`. Должны присутствовать все frameworks тестового
приложения этой версии. Checker создаёт только копии runtimeconfig в .runtime
и запускает собранные синтетические core/native проверки. Он не устанавливает
runtime, не меняет системные переменные, не запускает Rutony и не редактирует
его конфиг. CLI roll-forward Disable имеет приоритет над унаследованной
средой, поэтому проверяется именно запрошенная версия. Временные файлы остаются
в игнорируемом каталоге для проверки результата.

## Поддержка и переход

.NET9 поддерживается до10 ноября2026; .NET10 LTS — до14 ноября2028.
Нужна актуальная security patch-версия выбранной major. Версии в примерах
не являются рекомендацией фиксировать устаревший patch.
[Политика Microsoft](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).

Major не переключается автоматически, когда подходящая9 установлена.
[Выбор runtime Microsoft](https://learn.microsoft.com/en-us/dotnet/core/versions/selection).
После EOL код может продолжать работать, но addon не продлевает поддержку host.

План перехода: выбрать официальную vendor-сборку Rutony с поддерживаемым runtime;
сделать резервную копию приложения и данных; проверить сборку nativeCS против
её SDK и изолированные тесты; затем проверить загрузку расширения, события,
панель и штатное завершение/восстановление на тестовой установке. Переход всей
программы через собственный roll-forward, изменение её runtimeconfig или
замена frameworks не входят в установщик расширения. До реального host-прогона
не заявлять проверенные synthetic проверки как поддержку vendor версии.

## Границы ответственности

RutonyChat — стороннее закрытое приложение. Его поставщик выбирает runtime
и выпускает обновления host; расширение не обновляет и не перенастраивает
runtime приложения. Наш проект отвечает за совместимость своего пакета
с изученным SDK, собственные зависимости и проверки поведения расширения.
Расширение не продлевает поддержку и не обеспечивает безопасность
устаревшего runtime приложения.

При появлении официальной vendor-сборки проверяем native compile,
изолированные tests и затем ручную загрузку на выбранной версии.
Фактический список поддерживаемых Rutony builds подтверждается таким
ручным прогоном. До него не переносим synthetic PASS на реальную установку.
